# 使用说明

## 启动与角色

完成 README 中的依赖安装后，双击根目录的 `启动项目.bat`，打开 `http://127.0.0.1:8012/`。

首次运行先打开 `http://127.0.0.1:8012/merchant-setup`，从本机 `storage/workbench.credentials.json` 读取 `supervisor` 凭据后填写并读取配置。空库需要填写商家标识、名称和人员信息后初始化，再录入并审核商品、政策，导入订单并分配权限。

人员使用本人凭据在配置页登录进入工作台。初始化后，右上角的角色选择不会代替凭据认证；更换人员时，应从配置页使用相应人员的凭据登录。

## 客服操作

1. 在「处理咨询」选择已有工单，或点击「新建咨询」。
2. 确认商品、型号、用途和订单。缺少的信息先向客户询问。
3. 阅读客户原文及中文译文，查看引用资料。未配置模型服务时，可以手动编辑英文回复。
4. 编辑中文或英文回复，核对另一语言结果。翻译未完成时不能复制过期英文。
5. 保存并复制回复，在原沟通渠道发送。复制与记录发送分别操作；处理完成可选择「记录回复并结案」。
6. 需要售后时提交退款或补发申请，等主管审批后登记执行凭据。
7. 无法处理或需要额外权限时，使用「人工交接」升级。收到主管派回的工单后，按处理要求接单、记录结果并结案。
8. 重复出现的商品问题在「客户反馈」提交；商品与政策在「知识库」查询。

9. 「我的任务」只显示分派给本人的改进任务；接单、处理后提交交付，由主管确认实施与验收。

## 主管操作

1. 打开「主管待办」，处理待审批、待对账及分派给自己的升级工单。
2. 「售后审批」核对金额、商品数量、订单与政策。批准后由客服执行；本人申请需要另一名主管审批。
3. 对执行结果未知的申请核对凭据并对账，确认前不能直接重试。
4. 「异常调度」查看升级原因，记录处理决策，再派给有订单授权的客服跟进。
5. 「问题审核」整理反馈和核实原因，「改进管理」跟踪任务及效果。
6. 「知识管理」查询资料、审核发布与回滚；「服务质检」查看回答与回归结果。
7. 「管理工具」提供附件核验、数据管理和业务验证。商家配置从知识管理进入。

## 独立验证工作区

启动器还会启动端口 `8019` 的独立工作区。两个工作区首次启动均为空；业务验证的资料、案例和观测记录与 `8012` 的日常业务库分开保存。

## 停止服务

在项目根目录运行：

```powershell
python scripts/run.py --stop
```

使用虚拟环境时，将 `python` 替换为 `.\.venv\Scripts\python.exe`。关闭浏览器不会停止后台服务。
