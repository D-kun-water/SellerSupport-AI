# 产品分析与文档导航

版本：v1.3 · 2026-10-15。本文档包由早期产品合订材料整理修订，产品范围以当前代码和 [PRD](04_PRD.md) 为准。公开资料研究、产品判断、工程验证和商家业务结果分别记录。

## 1. 产品判断

SellerSupport AI 是面向数码配件经营团队的客服与商品改进工作台。它帮助客服完成有依据的咨询处理，让售后审批、人工交接、反馈归集和知识更新能够连续流转。

最强的反对意见是：成熟客服产品已经提供消息聚合、AI 草稿、订单上下文和自动化。仅有聊天框、双语翻译或文档问答，不足以形成购买理由。当前没有目标商家的成对工作量数据，不能断言本项目比现有工具更省钱。

因此，产品优先验证两个问题：型号、用途、来源版本与权限能否共同约束回答；客服反馈能否进入有负责人、有交付物、有后续观察的商品改进流程。两项判断仍需商家使用证据支持，不能用代码完成度替代。

## 2. 面向谁，处理什么任务

目标团队经营充电器、线材及相邻数码配件，有持续咨询、可维护的商品资料、明确售后政策，并愿意提供授权脱敏记录和业务负责人。

| 角色 | 核心任务 | 产品提供的帮助 | 当前账号角色 |
|---|---|---|---|
| 客服 | 查证、澄清、回复、申请售后、交接 | 工单上下文、来源依据、双语编辑、待办 | 客服 |
| 客服主管 | 审批、对账、调度、质检 | 队列、版本检查、操作历史、回归记录 | 主管 |
| 商品运营或商品负责人 | 核实问题、更新说明、提交交付 | 问题专题、证据、改进任务、知识发布 | 当前通过已有角色协作，未设独立运营账号类型 |
| 经营负责人 | 判断投入价值、决定采购 | 观察计划、人工时间与错误记录 | 业务参与者，未设独立账号类型 |

## 3. 核心流程与产品取舍

咨询进入工单后，客服核对商品、设备、用途和订单；系统查证适用资料，信息不足时澄清，资料冲突或异常时交人工。回复经人工核对后在原渠道发送，售后由主管审批，执行结果依据操作人提交的凭据登记。

重复问题从客户原文提名为反馈，经审核归组形成专题。负责人核实原因后创建改进任务，提交交付并记录实施时间；知识变更经过回归再发布，后续记录支持继续观察或回退。

| 决策 | 采用理由 | 代价与验证点 |
|---|---|---|
| 从数码配件切入 | 型号、接口、功率、用途和版本可以形成明确查证条件 | 需要逐项维护资料，不能跨型号推断 |
| 单商家本地应用 | 先验证一个团队的工作流与资料管理 | 尚不提供多租户隔离或云端运营能力 |
| 规则决定业务状态，模型辅助表达 | 金额、授权、审批和状态需要可复核结果 | 语言覆盖与规则覆盖有限，未知事项交人工 |
| 保留人工审批和外部凭据登记 | 当前没有交易、发货或消息渠道连接器 | 仍有跨系统操作成本，需要纳入业务测量 |
| 把问题改进纳入同一流程 | 让客服记录与商品内容变更保持关联 | 任务完成与业务效果之间仍需观察 |

## 4. 当前状态

代码已包含工单、规则查证、可选模型回复、双语翻译、退款与补发审批、人工交接、反馈专题、改进任务、知识版本和业务观察工作区。正常启动为空库；测试资料独立放在测试目录。

当前没有接通外部消息发送、支付退款、物流发货，也没有完成商家成效或付费验证。模型接口与质量检查代码存在，不代表已针对目标商家完成回答质量验收。
