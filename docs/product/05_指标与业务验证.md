# 指标与业务验证

版本：v1.3 · 2026-10-15。当前没有已确认的商家净节省、退货改善或付费结果。本文件定义后续如何取得证据。

## 1. 测量单位与条件

以一个可归属、可结案或可交接的业务任务为基本单位，不把单条消息数当成解决任务数。每条记录保存任务类型、商品与政策版本、授权范围、观察时间、基线处理方式和审核者。

同一任务出现多次消息、重开或返工，应保留关联；测试回放与授权业务记录分开统计，不拼成一个总体。删除或缺失记录影响覆盖，需要在结果中说明。

现有观察接口记录人工基线、等待、审核、返工和维护等字段。独立查找、外部操作等环节若未被字段完整覆盖，需另行补记；不能直接把当前接口汇总当成完整业务净收益。

## 2. 核心指标

| 指标 | 口径与单位 | 数据来源 | 需要避免的误读 |
|---|---|---|---|
| 任务正确完成比例 | 经审核满足期望的任务数 / 已审核任务数 | 原文、依据、操作和人工判断 | 生成了文字不等于完成 |
| 关键事实与来源错误 | 商品、条件、政策或状态错误的任务数及总审核数 | 人工审核及规则断言 | 有引用不等于引用支持结论 |
| 越权或错误执行 | 未授权读取、批准、执行或重复登记的次数与测试范围 | 接口结果、状态和审计 | 不能只看回复措辞 |
| 澄清与人工接管 | 必要信息是否补齐，交接是否带齐上下文 | 工单、缺失字段和交接记录 | 接管少不必然更好 |
| 单任务人工时间 | 查找、编辑、审核、外部操作、记录、返工的秒数 | 配对任务观察 | 不只统计模型响应时间 |
| 净节省时间 | 人工基线减去辅助后的人工负担与分摊维护时间 | 观测及维护记录 | 不自动转换为现金收益 |
| 质量与延迟 | 指定集合中的错误、P50/P95、失败和未知用量 | 运行记录 | 配置预算不等于实测性能 |
| 持续使用与采购 | 持续使用周期、实际采购和续用 | 经确认的业务记录 | 意向反馈不等于付费 |

不得在没有销量和成熟观察窗口时计算总体退货率或缺陷率。指标须同时报告样本数、分母、窗口、未审核数和缺测数。

## 3. 成本和价值公式

```text
净节省时间 = 同批任务的人工基线时间
             - 辅助后的查找、编辑、审核、外部操作、记录和返工时间
             - 分摊的知识维护与标注时间

产能释放价值 = 净节省小时 × 适用人工小时成本

可兑现净收益 = 经确认减少的支出或增量贡献
               - 模型、工具、基础设施及其他新增支出
```

一次性开发投入单列。排班、加班、外包或其他支出没有实际变化时，只报告工时或产能，不报告已经降低现金成本。改善与业务变化的因果关系需额外对照，不能靠前后两组数量直接认定。

## 4. 验证流程

1. 确认授权范围、业务负责人、资料版本、可执行政策和可取得的人工基线。
2. 以脱敏历史任务离线回放，保留成功、失败和人工接管案例，先检查高后果错误。
3. 通过后再进行不影响客户处理的并行观察；人工继续做实际决策。
4. 辅助使用阶段逐任务记录采纳、审核、返工和维护；在原渠道执行的记录由责任人核对。
5. 业务负责人结合覆盖、错误和净时间判断继续、调整或停止；缺少后续样本时保持数据不足。

已有代码支持计划、轮次、审核、配对测量与收口，但操作人员的记录不能独立证明授权、发送或外部回执真实性。[计划实现](../../app/pilot.py) · [观察记录](../../app/trial_records.py)。

## 5. 工程证据与业务证据

截至本次整理，已记录的验证包括：454 项后端回归通过；新增随机凭据用例所在的启动测试文件单独 6 项通过；11 项前端逻辑测试通过；20 个基础场景重复 3 次的规则回归共 60 次通过；前端构建通过。完整后端回归和新增用例的检查批次不同，不合并声称一次全量执行数量。

这些结果只支持对应代码、规则与测试输入。它们不能证明目标商家的回答语义、真实渠道可用、业务节省或独立留出集表现。原始本地运行记录不公开，以免混入业务资料或凭据；测试脚本和可复现命令见 [开发说明](../开发说明.md)。
