# 产品与业务规则

本文为简要概览，当前完整需求范围以 [PRD](product/04_PRD.md) 为准；产品背景、市场及需求判断见 [产品分析与文档导航](product/00_产品分析与文档导航.md)。

## 产品目标

帮助客服根据商品、政策和订单资料处理咨询；将重复问题归集为可审核的改进任务，更新知识后再验证回答质量。

## 角色

| 工作 | 客服 | 主管 |
|---|---|---|
| 日常咨询、回复与材料上传 | 处理 | 查看升级事项 |
| 售后申请和已批准申请的执行登记 | 处理 | 审批、未知结果对账 |
| 人工交接 | 发起、接单、处理、结案 | 决策、指派、跟踪 |
| 客户反馈 | 登记原文与问题 | 审核归组、核实原因 |
| 改进任务 | 接收本人任务、处理与提交交付 | 分派、调整负责人、确认实施与验收 |
| 知识与质检 | 使用已发布资料 | 发布资料、回归评测 |

主管首页仅显示需要本人审批或对账的事项、分派给自己的升级工单。普通咨询及等待客服执行的申请不计入主管待办；客服交付的改进任务进入待验收。

## 关键业务规则

1. 准确商品、设备型号与用途决定适配结论；资料未覆盖的组合保持未知。缺少必要信息先澄清，证据缺失或冲突时交人工。
2. 商品和政策按版本、地区与生效时间查证，回复保留对应来源。
3. 客户原文、附件和模型输出不能修改人员权限、订单事实或审批状态。
4. 退货窗口按可靠签收时间计算；资格判断、申请审批与执行记录分别管理。
5. 客服提交售后申请，主管核对后审批；申请人不能批准本人申请。
6. 批准后的售后由客服登记执行凭据；结果未知先交主管对账，不直接重试。
7. 人工交接由当前负责人处理，主管可给出要求并派回有订单授权的客服。其他人员不能代替负责人记录回复或结案。
8. 客户信息改变后，旧回复草稿需要重新核对；已解决或关闭的工单需重开后继续处理。
9. 修改中文或英文时，另一语言的旧文本失效；翻译未完成时不复制过期回复。复制与发送记录分别保存。
10. 重复反馈先核对原文与归组，再核实原因、创建改进任务、发布资料并观察效果。

## 页面分工

客服入口：处理咨询、我的任务、客户反馈、售后申请、人工交接、附件与对话、商品与规则。

主管入口：主管待办、售后审批、异常调度、问题审核、改进管理、知识管理、服务质检；附件核验、数据管理、业务验证放在管理工具中。

## 当前运行范围

应用使用本地单商家数据库，首次启动不含商品、订单或案例，需先配置商家并录入资料。模型服务可选；发送、退款与发货尚未连接外部渠道，应用保存操作人提交的执行凭据。质量结论与业务效果依据各自记录，不将规则回归通过率作为经营收益。
